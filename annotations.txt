What is Context? (The Big Picture)
Imagine you send three workers to fetch resources
from different places.
If one worker gets stuck or takes way too long,
you do not want them holding up everyone else,
wasting valuable time, and consuming resources that could be better spent elsewhere.
In Go, context is like a shared timer or a kill-switch.
Its primary purpose is to prevent the waste of computational energy and time.
When an operation takes longer than the value it produces—or when
the caller simply cannot afford to wait any longer—context
sends a signal across all running tasks saying: "Stop what you are doing, wrap up, and don't waste any more resources."

    func main() {
        fmt.Println("firing 3 requests..")

        // unsynchronized routines
        //go makeRequest(1)
        //go makeRequest(2)
        //go makeRequest(3)

        // wait for all requests to complete
        // time.Sleep(5 * time.Second)

        var wg sync.WaitGroup

        for i := 1; i <= 3; i++ {
            wg.Add(1)
            go func(id int) {
                defer wg.Done()
                makeRequest(id)
            }(i)
        }

        // we can have a request which it will gonna take 10 seconds
        // wg.Wait() will going to wait for all requests to complete
        // timeouts 10 sec -> request timed out
        wg.Wait()

        fmt.Println("Done!")
    }

    func makeRequest(id int) {
        fmt.Printf("[req %d] making request..\n", id)
        time.Sleep(3 * time.Second)
        fmt.Printf("[req %d] request done!\n", id)
    }
