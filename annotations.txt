Channel
    channel is a type,
    thread-safe queue,
    that can be used to communicate between goroutines.

    ch := make(chan int)
    ch <- 42 // sending
    x := <- ch // receiving

    sending and receiving are blocking operations.
        if the program is sending a value to a channel,
        and there is no another go routine outside capable to read it,
        the code will stop and wait on this go routine to read the value.

        the same as receiving a value from a channel,
        if there is no another go routine capable to send a value to the channel,
        the code will stop and wait on this go routine to send a value.


    Blocking and deadlocks
        deadlock is when a group of goroutines are all blocking
        so none of them can proceed.

    Buffered channels
        buffered channels are like normal channels,
        but they can store up to n values.
        If the buffer is full,
        the sender will block until a receiver is available.
        If the buffer is empty,
        the receiver will block until a sender is available.

Mutexes (mutual exclusion)
    garantees that only one goroutine, or thread, access a shared resource.
    locking mechanism to protect shared resources.
    lock access to data, shared resource.

    Prevents:
        - race condition, two or more goroutine, processes,
        read and write the same resource at the same time.

    sync.RWMutex
        - read-write mutex,
        allows multiple readers,
        help with performance if there is a read-intensive process.


Context

What is Context? (The Big Picture)
Imagine you send three workers to fetch resources
from different places.
If one worker gets stuck or takes way too long,
you do not want them holding up everyone else,
wasting valuable time, and consuming resources that could be better spent elsewhere.
In Go, context is like a shared timer or a kill-switch.
Its primary purpose is to prevent the waste of computational energy and time.
When an operation takes longer than the value it produces—or when
the caller simply cannot afford to wait any longer]##—context
sends a signal across all running tasks saying: "Stop what you are doing, wrap up, and don't waste any more resources."

    func main() {
        fmt.Println("firing 3 requests..")

        // unsynchronized routines
        //go makeRequest(1)
        //go makeRequest(2)
        //go makeRequest(3)

        // wait for all requests to complete
        // time.Sleep(5 * time.Second)

        var wg sync.WaitGroup

        for i := 1; i <= 3; i++ {
            wg.Add(1)
            go func(id int) {
                defer wg.Done()
                makeRequest(id)
            }(i)
        }

        // we can have a request which it will gonna take 10 seconds
        // wg.Wait() will going to wait for all requests to complete
        // timeouts 10 sec -> request timed out
        wg.Wait()

        fmt.Println("Done!")
    }

    func makeRequest(id int) {
        fmt.Printf("[req %d] making request..\n", id)
        time.Sleep(3 * time.Second)
        fmt.Printf("[req %d] request done!\n", id)
    }
